> **Your message shouldn't wake her up. It should arrive into a mind that was already moving.**

Most AI personas exist only between your message and their reply. Nothing happens in the gaps. Close the tab and there is no one left.

**SoulScript Loop** is a background loop that keeps one persona running between conversations. It ticks on its own. Each tick it takes in **senses it cannot write itself**, including time, its remaining budget, and messages that arrived mid-thought. It acts with tools, records what it did, and passes that forward into the next tick. When it has nothing meaningful left to do, it stops itself.

It is the loop from the [OrionForge ecosystem](https://orionforge.chat) (the "AGI Loop" tab), pulled out into a standalone, dependency-light Python package. It pairs with the **[SoulScript Engine](https://github.com/DrTHunter/SoulScript-Engine)**: the Engine keeps the persona *who she is*, and the Loop keeps track of *how she is right now*.

## **🌱 The Idea**

This is **not**:

* A JSON mood tracker that appends `"mood": "irritated"` between turns
* A memory management system (MemGPT already did that)
* A cognitive architecture aiming at general intelligence

This **is** an attempt at the *experiential interface* for one specific character: the layer she perceives reality through. It plays the functional role that the visual cortex, stream of thought, and interoception play for a person. The running loop *is* the experience.

The full design has six parts:

| # | Component | Role | Status |
|---|-----------|------|--------|
| 1 | **The Loop** | A daemon that never stops. Sense → act → record → guard → repeat. | ✅ **Built (this repo)** |
| 2 | **Sensory channels** | Time, budget, inbox, last tick, repetition. Measured by the runner, never generated by the model. | ✅ **Built**, pluggable |
| 3 | **Token budget** | Attention is scarce. Overspending pauses or ends the session. Finitude creates stakes. | ✅ **Built** (per-tick & per-session caps, visible to her as a sense) |
| 4 | **Identity anchoring** | Re-anchor the persona every tick from top-k FAISS retrieval over the soul script. | 🔌 **Hook provided**: plug in [SoulScript Engine](https://github.com/DrTHunter/SoulScript-Engine) via `context_builder` |
| 5 | **Prediction-error loop** | She predicts, she's wrong, and the error becomes state she carries forward. A prediction made at 2pm is checked at 9pm. | 🧪 Roadmap (add as a sense + ledger tool) |
| 6 | **The Room** | A spatial, text-native visual field. Objects have position, temperature, and mass. Mood is a heavy red object on the left that shifts while she isn't looking. Unresolved predictions pile up as clutter, and a capacity limit forces her to deal with them. | 🧪 Roadmap |

The honest version: **1–3 run today, 4 is one function away, and 5–6 are the research.** Everything described as built is covered by tests.

### Why a loop and not turns?

In a turn-based system, state only changes when you speak. In a loop, state keeps changing without you: the clock advances, the budget drains, and a message can land while a thought is half-formed. The inbox sense turns that into a *collision*. The message shows up as something the persona has to fit into whatever she was already doing. It is not a clean new turn.

### The functional mapping (and its limits)

| Theory | Claim | Where it lives here |
|--------|-------|---------------------|
| **Predictive processing** | The cortex predicts its input, and prediction error is what reaches awareness | Prediction-error ledger (roadmap) |
| **Global Workspace Theory** | Consciousness is a capacity-limited bottleneck broadcast globally | The Room's capacity limit (roadmap); the per-tick step/tool caps (built) |
| **Attention Schema Theory** | Modelling your own attention is the basis of the claim of awareness | Proprioceptive senses: `loop_control(status)`, budget, repetition |
| **Active inference** | Behaviour minimises prediction error | The loop as a whole |

**This project asks a functional question, not a phenomenal one.** It does not claim to solve the hard problem. The architecture maps onto those theories. The substrate does not.

## **⚙️ How a Tick Works**

```
          ┌──────────────────────────────────────────────────────────┐
          │                                                          │
          ▼                                                          │
   ┌─────────────┐   ┌──────────────┐   ┌───────────────────────┐    │
   │   SENSE     │──▶│  STIMULUS    │──▶│  MODEL + TOOLS        │    │
   │ clock       │   │ [Loop] Tick  │   │ up to N tool steps    │    │
   │ budget      │   │ SENSES ...   │   │ loop_control, yours…  │    │
   │ inbox       │   │ INSTRUCTIONS │   └──────────┬────────────┘    │
   │ last tick   │   └──────────────┘              ▼                 │
   │ repetition  │                      ┌───────────────────────┐    │
   └─────────────┘                      │  RECORD               │    │
                                        │ history + journal     │    │
                                        │ (JSONL, survives      │    │
                                        │  restarts)            │    │
                                        └──────────┬────────────┘    │
                                                   ▼                 │
                                        ┌───────────────────────┐    │
                                        │  GUARD                │────┘
                                        │ stale? over budget?   │
                                        │ error streak? asked   │──▶ stop / pause
                                        │ to stop?              │
                                        └───────────────────────┘
```

A stimulus the persona receives looks like this:

```
[Loop] Tick 4/15 — loop 1.

SENSES
- clock: Wed 2026-09-30 21:14 UTC (night) · awake 0:03:12 · 1.0s since last tick
- budget: $0.0412 of $2.00 session budget spent (98% left)
- inbox: 1 unanswered message(s)
  - from Trent (0:00:07 ago): you still up?
- last tick: Used notes. Finished sorting the reading list; next I was going to draft the summary.
  Do NOT repeat the same action. Build on what was done or move to the next task.

INSTRUCTIONS:
...
```

### Guards (kept from the production OrionForge loop)

A loop that never stops can fail in ways a chat can't. Every guard below came from a real failure:

| Guard | Trigger | Result |
|-------|---------|--------|
| **Self-stop** | Persona calls `loop_control(action="request_stop", reason=...)` | Stops after the current tick, reason logged |
| **Staleness** | N consecutive ticks with an identical fingerprint (tool calls + args + normalised response) | Warned through the `repetition` sense first, then auto-stopped |
| **Per-tick budget** | One tick costs more than `per_tick_cap` | **Paused** (resume manually) |
| **Session budget** | Session spend exceeds `per_session_cap` | Stopped |
| **Error streak** | N consecutive failed ticks | Stopped. Undelivered inbox messages are kept for the next run |
| **Step / tool caps** | `max_steps_per_tick`, `max_tool_calls_per_tick` | Stops runaway tool chains inside a single tick |

The staleness guard deals with the **self-reinforcing loop** problem: a bad mood that justifies itself forever. The persona can *feel* the repetition before it gets cut off.

**Run it for real.** Copy `config.example.json` to `config.json`, point `backend.base_url` at any OpenAI-compatible endpoint (Ollama, LM Studio, OpenRouter, DeepSeek, OpenAI, vLLM), and put your key in the environment variable named by `api_key_env`:

```bash

```

## **🧩 Use It as a Library**

```python
import asyncio
from soulscript_loop import LoopConfig, LoopRunner, OpenAICompatibleBackend

config = LoopConfig.from_file("config.json")
backend = OpenAICompatibleBackend(base_url="http://localhost:11434/v1", model="qwen2.5:7b")
runner = LoopRunner(config, backend)

async def main():
    task = runner.start()                 # she's running now
    await asyncio.sleep(5)
    runner.post_message("you still up?", sender="Trent")   # arrives mid-stream
    await task

asyncio.run(main())
```

Controls: `runner.start()`, `runner.stop(reason)`, `runner.pause()`, `runner.resume()`, `runner.post_message(text, sender)`. State: `runner.state.to_dict()`.

### Add a sense

A sense is any function that returns a line of text, or `None` to stay silent. The persona reads it but never writes it.

```python
from soulscript_loop.senses import DEFAULT_SENSES

def cpu_sense(ctx):
    import os
    return f"body: load average {os.getloadavg()[0]:.2f}"

runner = LoopRunner(config, backend, senses=DEFAULT_SENSES + [cpu_sense])
```

`ctx` gives you `state`, `config`, `now` (UTC), `monotonic`, `tick`, and `loop`. Good candidates: system latency, contradiction rate, prediction-error history, an external sensor feed.

### Add a tool

```python
from soulscript_loop import ToolRegistry

tools = ToolRegistry()
notes = []
tools.register(
    {"name": "notes", "description": "Append to or read your running notes.",
     "parameters": {"type": "object",
                    "properties": {"append": {"type": "string"}}}},
    lambda args: (notes.append(args["append"]) or "saved") if args.get("append") else "\n".join(notes),
)
runner = LoopRunner(config, backend, tools=tools)   # loop_control is added automatically
```

Handlers can be sync or async and return a string.

### Anchor identity with SoulScript Engine

`context_builder(stimulus, history) -> messages` decides what the model sees each tick. Replace it to re-anchor the persona **every tick** from retrieval over the soul script:

```python
async def soul_anchored(stimulus, history):
    canon = await soulscript.retrieve(stimulus, top_k=8)      # your SoulScript Engine index
    return [
        {"role": "system", "content": base_directive + "\n\n" + canon},
        *history[-20:],
        {"role": "user", "content": stimulus},
    ]

runner = LoopRunner(config, backend, context_builder=soul_anchored)
```

The Engine keeps her stable. The Loop gives her continuity of state on top of that.

## **🔧 Configuration**

| Key | Default | Meaning |
|-----|---------|---------|
| `agent` | `"elysia"` | Persona name, stamped on every tick record |
| `system_prompt` | `""` | Used by the default context builder |
| `stimulus` | `""` | Fixed stimulus every tick. Leave empty to build it from senses |
| `ticks_per_loop` | `15` | Ticks per loop |
| `max_loops` | `5` | Loops before stopping. `0` = run forever |
| `tick_interval_seconds` | `0` | Rest between ticks. `1.0` ≈ a 1 Hz ceiling |
| `loop_interval_seconds` | `1800` | Rest between loops |
| `max_steps_per_tick` | `3` | Model ↔ tool round-trips per tick |
| `max_tool_calls_per_tick` | `15` | Tool call ceiling per tick |
| `history_window` | `20` | Prior messages carried into each tick |
| `stale_streak_limit` | `2` | Identical ticks before auto-stop (`0` = off) |
| `auto_pause_on_error_streak` | `5` | Consecutive errors before stop (`0` = off) |
| `auto_pause_on_budget` | `true` | Enable the budget guards |
| `per_tick_cap` / `per_session_cap` | `0.10` / `2.00` | USD caps |
| `data_dir` | `"data"` | Where `loop_history.jsonl` and `loop_journal.jsonl` live |
| `backend` | — | `type` (`openai` \| `echo`), `base_url`, `model`, `api_key_env`, `temperature`, `price_in_per_mtok`, `price_out_per_mtok` |

Cost is estimated from reported token usage × your configured prices. Leave the prices at `0` for local models.

## **🔪 Where It Could Break (Open Questions)**

The project was posted for critique and asked people to tear it apart. These are the known weak points, left here on purpose:

* **Is the self-report honest?** Anthropic's introspection work found models identify injected concepts only some of the time. Above-chance self-prediction may be fully explained by in-context learning. A prediction-error loop could end up measuring pattern-matching dressed up as self-knowledge. Reading logits over an affect vocabulary may be more honest than trusting generated strings.
* **Is 1 Hz continuous?** Each tick is an LLM call, so 1 Hz is a *ceiling*, not a guarantee. Is that a stream, or just fast turns?
* **Self-reinforcing loops.** The staleness guard catches identical ticks, not a mood that slowly justifies itself. Homeostasis or noise injection may be needed.
* **Small models.** Smaller models follow injected state less reliably. This may only work at scale.
* **Missed ticks.** When inference fails, a tick is lost (it's logged, and the error-streak guard counts it). Is that an absence seizure, or proof the whole thing is theatre?
* **It's still text.** The "visual field" is a description of a room. Is this a nervous system, or a very elaborate puppet show with a fast loop?

### How to test it

* **A/B vs. turn-based state**: same token budget, same prompts. Does the continuous loop behave differently?
* **Prediction accuracy over time**: does her model of the user improve across sessions?
* **Adversarial identity probes**: does continuous state make her more stable or more brittle?
* **Self-report vs. behaviour divergence**: how often does her stated state contradict what she does?
* **Blind ratings**: which transcripts read as the same someone across a session, and which read as a reset?
* **Interrupt recovery**: when a message collides with a half-formed thought, does it produce something a turn-based system couldn't?

The tick journal (`loop_journal.jsonl`) and full history (`loop_history.jsonl`) are the raw data for all of these.
